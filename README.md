# 拾光——校园失物招领

这是 2026 年秋季软件工程课程结对编程作业项目。项目计划使用原生 HTML、CSS 和 JavaScript，制作一个适合 PC 端直接打开的响应式校园失物招领网页，并在电脑上呈现居中的手机风格界面。

## 当前进度

已完成项目初始化、首页与信息卡片、首页交互优化、页面高度修复、寻物/招领信息发布模块、关键词搜索、物品详情与联系方式弹窗，以及我的发布和状态更新。

## 运行方法

无需安装依赖、启动服务器或配置数据库。使用 Google Chrome 直接打开项目根目录下的 `index.html` 即可运行。

发布的信息和本地发布者标识保存在浏览器 `localStorage` 中；首页演示数据仍由脚本集中维护，与用户发布记录分开读取和展示。`localStorage` 仅保存当前浏览器本地数据，不具备跨设备同步功能。清理浏览器站点数据或更换浏览器后，本地发布内容不会自动迁移。

“我的发布”仅按当前浏览器保存的本地发布者 ID 筛选记录。这只是本地归属标识，不是账号、登录或实名认证，不能证明现实身份；也不提供跨设备共享。

## 详情与联系方式

- 首页、搜索结果和发布成功页均使用物品 ID 打开同一个详情页，显示寻物/招领字段及当前状态。
- 详情地址片段为 `#item=物品ID`（特殊字符会编码）。切换地址中的 ID 或刷新后，使用该 ID 从示例及当前浏览器已保存记录中恢复；切换物品会关闭旧联系方式弹窗。地址不包含联系方式。无效 ID 会聚焦找不到信息的提示，损坏的本地数据不会被覆盖。
- 页面内返回按钮保留本次会话的首页筛选或搜索结果、关键词和滚动位置；从发布成功页进入时返回成功页。刷新恢复详情后，返回按钮默认回到首页。
- “查看联系方式”使用原生模态 `dialog`：打开后聚焦关闭按钮，支持 Tab 循环和 Esc 关闭，关闭后焦点返回原按钮。示例没有虚构的联系方式，会显示暂未提供的提示。
- 一键复制使用 `navigator.clipboard.writeText`，只在成功后提示“复制成功”。等待期间保留弹窗内键盘焦点并阻止重复请求；关闭后忽略旧请求回调。`file://` 下权限或 API 支持可能不同；失败时给出提示并选中只读文本，也可直接使用“选中全部，手动复制”，按 Ctrl+C（Mac 为 Command+C）或长按、右键复制。联系方式类型根据手机号格式提示；无法确定的内容标注为“微信号或其他联系方式”。
- 详情查询接口为 `ShiguangLogic.getItemById(items, id)`，应用内也提供 `ShiguangApp.getItemById(id)`；使用严格字符串 ID，找不到时返回 `null`。现有存储字段及版本不变。

## 我的发布与状态更新

- 底部“我的发布”显示当前浏览器发布者 ID 对应的记录，不包含首页演示数据；卡片按发布时间倒序排列，可筛选全部、进行中及已完成。
- 状态更新入口仅从“我的发布”记录详情进入。寻物从“寻找中”变为“已找到”，招领从“待认领”变为“已归还”；示例记录、其他发布者记录和已完成记录不能更新，完成状态不可撤回。
- 状态通过现有 `shiguang.items.v1` 键按 ID 更新，保留其它字段、发布时间及历史记录。损坏数据或写入失败会显示错误，不会显示成功状态。
- 更新后首页、已存在的搜索结果、我的发布列表及详情会同步状态，刷新页面后状态保留。详情仍可查看完成记录及其联系方式。

## 自动化检查

仅开发测试需要本机 Node.js，网页运行不需要安装 Node.js 或任何依赖：

```powershell
node --test tests/*.test.js
Get-ChildItem js,tests -Recurse -Filter *.js | ForEach-Object { node --check $_.FullName }
git diff --check
```

当前共 117 项测试：发布/首页/搜索39项、详情42项、状态与“我的发布”36项。状态测试覆盖浏览器 `NodeList` 键盘导航、首次发布生成本地 ID、空白或保留的发布者 ID；存储会丢弃这些无效身份，避免本人发布被过滤。测试覆盖业务分支、存储失败、筛选统计、跨页面同步和弹窗键盘交互。交互测试使用轻量 DOM 和本地存储模拟，不能代替真实浏览器验证。

阶段 6B 另用独立配置的 Chrome 155 无头模式直接打开本地 `index.html`，通过 46 项浏览器断言：原生键盘、详情及刷新、搜索返回滚动位置、发布回归、Clipboard API 实际写入与读取、280/320/375/1280px 宽度及 320×360px 矮窗口布局，未出现未捕获异常。复制拒绝、API 缺失及等待竞态通过注入模拟；没有将它们计作系统权限弹窗测试。

阶段 7B 使用独立 Chrome 配置直接打开本地页面，通过 34 项状态模块浏览器检查：空列表、身份隔离、筛选统计、方向键筛选、确认/取消与焦点、存储损坏及容量错误、首页/搜索/详情同步、刷新持久化，以及 280–430px 窄屏布局；未出现未捕获异常。

人工复核可按以下步骤进行；屏幕阅读器实际播报、实体手机长按复制及系统权限弹窗仍需人工验证：

1. 直接打开 `index.html`，分别从首页、搜索结果、发布成功页进入详情并返回；在详情页刷新。
2. 发布不同联系方式的两条信息，确认弹窗只显示当前记录；确认 Esc、Tab/Shift+Tab 和关闭后的焦点。
3. 检查真实复制结果；拒绝剪贴板权限时尝试选中手动复制；查看没有联系方式的示例。
4. 在窄屏、较矮窗口及长描述/长联系方式下，检查换行、滚动、底部导航和横向溢出。
